# cup-session-characterization Specification

## Purpose
Pins the observable per-tick behaviour of a running cup session (scores, racer feedback, chat and title lines, log
text, the `/race` status block, and the order of the per-tick steps), so that moving cup code between modules
cannot change it without a failing test. It is the reference the refactor is judged against, not a change to what
the cup does.

## Requirements

### Requirement: A Golden Master pins each cup scenario tick by tick
**Priority:** MoSCoW Must

THE SYSTEM SHALL keep four Golden Master scenarios for a running cup: lobby and start, racing with a boost and a
disconnect, skip and map and cup finish, and restart with a pending catalogue. For every tick of a scenario, the
transcript SHALL record the full `describe()` text, the chat and title messages each racer received in order, and
the log lines the cup wrote. The transcript SHALL equal the committed golden file for that scenario.

#### Scenario: Transcript matches the committed golden file
- **WHEN** the lobby-and-start scenario runs against the production code
- **THEN** its transcript equals `voyager-server/src/test/resources/golden/cup-session/lobby-and-start.txt` line for line

#### Scenario: A changed message fails the scenario
- **WHEN** one message string of the cup is changed by one character
- **THEN** every scenario that delivers that message fails and names the first differing tick and line

### Requirement: The golden files are the pre-move behaviour and are never regenerated by the move
**Priority:** MoSCoW Must

THE SYSTEM SHALL generate the golden files from the production code of `main` before the first code move of this
change. The test SHALL NOT rewrite a golden file. Each move commit SHALL leave every golden file byte-identical.

#### Scenario: Move commit touches a golden file
- **WHEN** a commit of this change modifies a file under `src/test/resources/golden/cup-session/`
- **THEN** the change is rejected unless the commit is the one that adds the file

#### Scenario: Mismatch writes the received transcript to a temporary directory
- **WHEN** a scenario's transcript differs from its golden file
- **THEN** the received transcript is written to a `@TempDir` and the test fails, leaving the golden file unchanged

### Requirement: The transcript pins text and level, not the logger category
**Priority:** MoSCoW Should

THE SYSTEM SHALL record each log line of a scenario as its level and its formatted message. The logger name SHALL NOT
be part of the transcript, because moving a class changes its logger category, and that is the one difference this
change is allowed to make in log output.

#### Scenario: Logger category changes after the move
- **WHEN** `CupSession` moves from `server.game` to `platform.cup`
- **THEN** the golden transcript is unchanged, because only the level and the message are recorded

### Requirement: The characterization is deterministic and never waits on the wall clock
**Priority:** MoSCoW Must

THE SYSTEM SHALL drive every scenario by explicit ticks of the per-tick pipeline, with a fixed `java.time.Clock`, fixed
player names and fixed player identities, and no `Thread.sleep` or wall-clock read. Each scenario SHALL build its own
server instance, so that no scenario depends on another or on execution order.

#### Scenario: Scenarios run in reverse order
- **WHEN** the four scenarios run in reverse order, or in parallel
- **THEN** every transcript is identical to the one from a forward run

#### Scenario: Scenario waits or reads the wall clock
- **WHEN** a scenario calls `Thread.sleep`, or reads `System.currentTimeMillis`, `System.nanoTime` or `Instant.now`
- **THEN** the review check against F.I.R.S.T. rejects the test
